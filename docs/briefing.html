Wordle at 0.5B

Distilling a classical Wordle solver into a half-billion-parameter language model — what worked, what the measurements kept overturning, and the one controlled experiment that is built and waiting to run.

Where it stands, in one screen

Everything below is detail on these six lines

  • The number is 3.7642 mean guesses, 242 of 246 held-out answers solved. That beats classical random elimination (4.0203) and letter-frequency heuristics (3.7927), and sits 0.32 behind a solver that plays near-perfectly (3.4431).
  • Most of that came from the decoder, not the model. Restricting each guess to words still consistent with the feedback was worth ~1.5 guesses. But the model is not a passenger: picking at random among those same admissible words scores 5.1762, so the model contributes +1.41 guesses of real skill.
  • Four separate training interventions moved the number by ±0.03. Endgame-heavy data, preference learning, threshold tuning, more epochs. One preference run made it measurably worse.
  • Prompt format matters more than any of them — but only downward. Twelve prompt formats span 1.24 guesses, and every single one is worse than the format the model was trained on. That is brittleness, not leverage.
  • The training set is far less varied than its row count suggests. 19,212 rows are only 13,872 distinct boards, and 13,814 of those sit at ten-or-fewer candidates. Above ten, the entire corpus holds 58 distinct boards.
  • One confound underlies every prompt result, and the experiment to break it is built. Phase 10, prepared and not yet run. Section 06.
Reading this project

The useful content is not the final number — it is the sequence of confident diagnoses that measurement overturned. Four are logged in section 07, including one retracted the same week it was written. Where a claim here is fragile, it says so.

01

The system

Four moving parts, only one of which is a neural network

The premise: build a classical Wordle solver that plays near-optimally, use it to generate expert demonstrations, fine-tune a small language model to imitate them, and find out what transfers.

1 · The classical solver (the teacher)

No machine learning. It holds the set of answers still consistent with all feedback so far, and picks the guess that minimises expected remaining candidates — an information-theoretic choice, computed exactly. It opens SALET every game and averages 3.4431 guesses, failing none.

2 · The prompt (the board, written down)

Each decision becomes a text prompt: the rules, the guess history with its G/Y/B feedback, a block of deductions computed by the solver (Confirmed letters, Letters present, Letters absent, Ruled-out spots), and the turn counter. It ends in Next guess:. The candidate count is never shown — that is privileged information a player cannot see.

That solver-computed deduction block is the single most consequential design choice in the project, and section 06 is entirely about it.

3 · The model

Qwen2.5-0.5B-Instruct with a LoRA adapter (r=16, α=32, seven target modules). Trained on prompt → expert-word pairs with the prompt masked out of the loss. The current best adapter is tree_salet_endgame, trained on 19,212 rows for 2 epochs.

4 · The decoder (where the win came from)

The model never emits free text. All 12,972 legal Wordle words are scored, and the highest-scoring one is played. Crucially the candidate list is filtered to words consistent with the feedback already received — but only once the game has narrowed. That threshold matters:

  • Always filtering hurts. The expert's own turn-2 move is feedback-inconsistent 59% of the time — it probes with a word that cannot win, to extract information. An always-on filter forbids that.
  • Never filtering hurts more. The model hallucinates words inconsistent with its own board.
  • Adaptive@20 — probe freely above 20 remaining candidates, enforce consistency below — is the plateau. That is the 3.7642 configuration, and it is held fixed in every experiment since, so nothing gets attributed to the prompt that belongs to the decoder.
The measurement discipline

Every comparison is paired on identical answers, because unpaired standard error on 246 games is ~0.064 guesses and would hide every effect of interest. Every decision is tagged forced (the filter left one word, the model contributed nothing) or model_chosen. A no-model control — pick uniformly at random among admissible words — runs alongside, so a decoder win cannot masquerade as a model win.

03

The three findings that matter

And how confident each one is

1. The decoder did most of the work solid

Feedback-consistent decoding was worth ~1.5 guesses. Everything learned across phases 4–6 was worth a fraction of that. This is the project's headline and it is uncomfortable: the impressive number belongs substantially to a hand-written constraint, not to learning.

The counterweight is the no-model control. Playing the same 246 games by picking uniformly at random among admissible words scores 5.1762. The model scores 3.7642 on the same decoder. So it is contributing 1.41 guesses of genuine skill on top — largely a learned probing policy that beats a random probe.

2. The scaffolding may be doing part of the reasoning strong, but confounded

The prompt hands the model deductions the solver computed. Remove that block (the raw_history variant) and the mean degrades 0.52 guesses and ten solved games. With the decoder switched off entirely, that same model emits 1.4% admissible words against the baseline prompt's 22.3% — while emitting more legal words. It keeps the rules of Wordle and loses the deduction.

The confound: the adapter only ever saw the baseline format. "The block is load-bearing" and "the model recognises the only format it was trained on" predict exactly the same table. Phase 10 exists to separate them.

3. The training data is far thinner than it looks solid

19,212 rows, 13,872 distinct boards, and only 58 of those above ten remaining candidates. The cause is structural, not an oversight — see section 05. It inverts the intuitive fix: the endgame is the data-rich half.

The most fragile number in the project

Finding 1 rests substantially on a single random-among-admissible baseline. It has been measured, it is internally consistent, and it has never been independently re-derived by a different method. Probe it before building on it.

A second, unremovable caveat: the Wordle answer list is almost certainly in Qwen's pretraining data. "Generalisation to unseen answers" therefore carries a confounder that can be stated but not eliminated.

Two things went wrong, and both were instructive

Defect 1 — the few-shot variant measured copying

Its two worked examples ended Next guess: BOBBY. The model copied the last one and opened BOOBY on all 100 games. Its 6.06 measured verbatim copying, not few-shot learning.

Fixed: eight exemplars rotating per board, so a copier cannot produce one stable word, plus a measured shot_copy_pct. On the re-run it reads 0.0% — the variant is now a real measurement, and it still scores 5.00. Few-shot prompting genuinely does not work here.

Defect 2 — the control arm answered nothing

A stock, untrained Qwen arm was run specifically to break the lock-in confound, on the reasoning that all twelve formats are equally unfamiliar to it. All nine runs landed at 6.71–6.88 mean with 91–97% failure and a spread of 0.17. A model that cannot play Wordle under any prompt cannot rank prompts. It consumed 84.5% of the session's wall time and settled nothing — which is precisely why Phase 10 trains a second adapter instead.

The framing that survives

No variant beat baseline. The best alternatives are statistical nulls and everything else degrades. So "prompt format is worth 25–75× what training was" conflates two different claims: brittleness (a bad prompt breaks a single-format 0.5B adapter — unsurprising) and leverage (a better prompt could improve it — for which the measured evidence is a null). Only the first is supported.

How the failures actually look

All four baseline losses share one shape. The model narrows the field correctly, then cycles through rhyming near-misses while the true answer stays admissible the entire time:

Every guess after turn 2 is admissible — no rule is being broken. The model is ranking near-neighbours badly. Of the 222 games that narrow to ten-or-fewer candidates, 1.8% are still lost (raw_history 5.7%, few_shot 8.2%).

This matters because it is not a coverage gap. That band already holds 79% of all training rows. It is a discrimination failure among words that differ by one letter.

A side result worth more than it looks

The 100-game and 246-game runs share 100 answers. All 300 shared per-game scores are bit-identical across two independent cloud sessions on different notebook versions. Phase 8b's baseline that would not reproduce was a bug loading the wrong adapter, not latent nondeterminism — so the doubt that hung over every paired comparison in this project is retired.

05

The training-data audit

Prompted by an obvious question, and it answered the opposite way

The model narrows the field well and finishes badly. The natural conclusion is that it has not seen enough examples of finishing. Every training row records how many answers were still consistent when it was captured, so that conclusion can simply be checked — and counting rows is not the same as counting distinct situations.

The cause is that a good solver is a fast solver. It opens SALET every single game, so all 2,069 opening rows are one board copied two thousand times. Turn two has only 141 distinct boards, because there are only so many feedback patterns SALET can return. The expert reaches a decisive position within three moves and the game ends. Its own competence is what starves the record of interesting middles.

The finding

The model did not learn to narrow the candidate set from abundant data. It learned it from 58 distinct positions, and does that part well. It learned to finish from nearly fourteen thousand, and that is the part it does badly. "We have not used much data" is correct — but the shortage is at the start of the game.

Was endgame-only training already tried?

Close to it. Phase 6 built 12,145 synthetic endgame states and mixed them in. That synthetic set is pure endgame — every row at ten candidates or fewer — and nearly twice the size of the expert data it joined. The result is a training set that is 79% endgame by row and 99.6% by distinct board.

Games solved before: 108. Games solved after: 108. Exactly zero change. The targeted skill did improve — picking the right word from a narrowed board went from 20% to 27.5%, generalising to unseen words at p=0.031 — which is why the decoder, not the data, turned out to be the binding constraint one phase later.

Training on endgame data alone, with the opening removed entirely, is the one version never run. It is cheap to build. But it pushes harder on the side of the distribution that already holds 99.6% of the variety, and the last time that lever was pulled it bought a measurable skill gain and no games.

06

Phase 10 — the format crossover

Built, pre-registered, and waiting. This is what the previous discussion was about.

The problem it solves

Every prompt result in the project is confounded in the same way. The adapter was trained on the baseline format alone. So both of these observations —

  • baseline beats raw_history by 0.516 guesses and ten solved games;
  • with the decoder off, the model emits 1.4% admissible words under raw_history against 22.3% under baseline

— are equally consistent with two incompatible stories. Either the solver's deduction block is genuinely load-bearing, or the model simply recognises the only format it has ever seen. Format lock-in and an intrinsic property of the format predict an identical table.

Phase 9 tried to break the tie with an untrained-model arm and could not, for the reason in section 04. Breaking it requires a model with real skill under a second format — so one gets trained.

What is held identical

Everything except the prompt string: the same 19,212 rows, the same completions (same expert action per row), the same metadata, the same LoRA configuration, the same learning rate and epoch count, the same seed — so even the shuffle order matches. The decoder at evaluation stays adaptive@20, and the 246 evaluation answers stay paired. If any hyperparameter differed, the experiment would be varying two things at once and would answer nothing.

The transformation, and why it is trustworthy

The training rows do not store the game history as data — only as text inside the already-rendered baseline prompt. So the history is parsed back out of that text. Before a single row is used, the parse must prove itself:

v_baseline(turn, parsed_history, max_guesses) == stored_prompt   byte-for-byte

If the parsed history reproduces the stored prompt exactly, the parse lost nothing, and the only difference in the output is the variant. Any mismatch aborts the run rather than writing a row. Verified against all 19,212 training rows plus the 853-row validation split: 20,065 exact round-trips, zero parse failures.

The pre-registered reading

Written before the run, and including the awkward outcomes. Phase 9's decision table failed to anticipate its own result shape — large spread, all negative — and that is exactly how a decision stays open.

A — Lock-in
each adapter best on its own format

Format is a robustness problem, not a quality ranking. Phase 9's ordering of the twelve variants says nothing about which prompt is intrinsically better, and the honest write-up becomes "this model is brittle to prompt format". The deduction block stays because it is what the model was trained on, not because it is doing hidden work.

Follow-up: one adapter trained on all non-leaky formats at once, with the pre-registered expectation that hard-mode violations fall.

B — Learnable
rawhist adapter recovers toward 3.76

The deduction the solver currently hands the model can be learned. The block was a crutch for this particular adapter, not a requirement, and the "the harness is the model" worry mostly dissolves. The interesting question then becomes why the block was ever needed — and whether a block-free model generalises where the scaffolded one does not.

C — Intrinsic
rawhist adapter stays near 4.28

The deduction genuinely exceeds what a 0.5B model learns at this data scale, even when trained directly on it. The block is honest scaffolding and stays. This is the cleanest outcome for the write-up: the harness does part of the work, it has to, and there is now a controlled experiment behind saying so.

D — Both worse than expected
check training first

If the new adapter underperforms on both formats, training is the suspect, not format. Check the step count against Phase 6's 1,202 and the loss curve against 5.886 → 0.741 before concluding anything about prompts. The notebook prints both comparisons for exactly this reason.

Not a valid reading in any branch

Treating a single 246-game cell as significant on its own. Cells are compared paired on identical answers, and failure counts are read on 246 only — the 100-game subset was actively misleading about failures, which is the retraction logged in section 07.

07

Corrections log

Five confident diagnoses, each overturned by a later measurement

This is the part of the project worth reading closely. Each entry was a well-motivated theory that survived review and was killed by data.

1 — the vocabulary theory

Claim: the model fails because the answers were held out of training, so it has never written those words. Test: make invalid words impossible to emit. Result: bought 0.49 guesses; the model still lost to random elimination. Vocabulary was a contributor, not the cause.

2 — the endgame-data theory

Claim: the endgame is starved of examples, so supply more. Test: 12,145 new endgame states, multiple routes per word. Result: 108 games solved before, 108 after. The targeted capability improved measurably and won nothing. Section 05 later showed the endgame was the data-rich half all along.

3 — a miscounted statistic

For several days the write-up claimed the endgame had "6 training examples out of 7,173". The number was real but measured a narrow flag for boards with all five letters confirmed. Actual coverage was 1,612 examples. The corrected framing — one route per word, not too few examples — is what produced the experiment above.

4 — the preference-learning theory

Claim: the model needs to learn comparisons, not single answers. Test: 14,923 preference pairs aimed at the exact states holding three quarters of the gap. Result: the preference was learned (accuracy 0.60 → 0.84) and gameplay got significantly worse (paired t = −3.21, 70 games worse against 38 better).

Diagnosis, and it is reusable: 64% of the pairs compared an obviously good move to an obviously bad one. Those cheap comparisons dominated the gradient, so the model spent 390 of 466 steps growing more confident about things it already had right, drifted from a working policy, and paid for the drift in play. Accuracy had saturated by step 75. The same failure mode threatens GRPO with more compute and less stability.

5 — the softening of finding 2 retracted same week

Claim: removing the deduction block only makes the model slower, not worse — it solved 98/100 against baseline's 97, so the block accelerates deduction rather than gating it. Test: the same comparison at full scale. Result: a sampling artifact.

The subset happened to contain almost none of the games raw_history loses. Means were stable across sample sizes; failure counts were not — and since a failure is scored at the seven-guess cap, failures are what make a variant expensive. Report failure rates on the full set only.

Two further errors were caught by automated checks rather than by reading: a sampled audit reporting "206 violations" when the true rate was 19%, and a preference dataset where 19% of pairs referred to moves the model could never make. Both would have trained cleanly and produced meaningless results.

08

Infrastructure and known traps

The operational context the experiments run inside

All training and evaluation runs on a single cloud T4 GPU session per phase, driven entirely through an API script rather than a browser. A notebook generator produces each phase's notebook from a Python source file, inlining the shared solver and prompt modules at generation time — so editing a core module without regenerating silently runs the old code.

Traps that have each cost a session

  • Never substitute an adapter. A lookup that fell back to "any adapter it could find" once loaded the wrong model and produced an entirely plausible wrong result — that is what voided Phase 8b. The lookup is now exact-match and refuses to substitute.
  • Check the gate before believing a number. Every evaluation run first reproduces a known configuration on 40 games. A wrong opening word means the wrong model is attached; stop rather than interpret the sweep.
  • An off-distribution prompt is ~13× more expensive to evaluate, and the mechanism is understood: the decoder scans candidate words in chunks and stops early once no unscanned word can win. A confident model prunes after one chunk; an uncertain one scans all 26. Predicted worst/best ratio 13, measured 13.2. Budget by expected model confidence, not prompt length — the shortest prompt in the sweep was among the slowest.
  • A convenience feature must never decide whether a run passed. A results auto-upload step raised an exception when credentials were absent, the notebook environment then crashed while formatting that exception, and a fully successful run was reported as a failure — with all results already saved. Nothing in that step can raise now.
  • Run everything as a committed job, never interactively. One session's results existed solely as a browser download because it was run by hand; they were nearly lost, and recovering them is what made the section-05 audit possible at all.
Where the code lives

core/ holds the solver, the constrained decoder and the twelve prompt variants — shared by every phase. Each phaseN_*/ directory holds its notebook generator, the generated notebook, and a technical document. phase9_harness/TECHNICAL.md carries the full Phase 9 record including the retraction; phase10_crossover/RUN.md carries the crossover's pre-registered design.

Model: Qwen2.5-0.5B-Instruct with LoRA. Hardware: one T4 session per phase. Evaluation: 246 held-out answers throughout, paired, failures scored as seven guesses. Every dataset ships with an audit that re-derives each training state from its own prompt and asserts the labels — the automated checks in this project have caught more real bugs than manual review has.
