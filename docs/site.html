What this is

The premise, and why the answer turned out to be surprising

Wordle is solved. Not approximately — solved. A classical algorithm using information theory finds the answer in an average of 3.42 guesses and never fails. There is no open question about how to play it well.

So this project asks a different question: if you take that algorithm’s decisions and use them to train a small language model, does the model learn to play, or does it learn to imitate? And when it fails, what exactly is the failing part?

The model is Qwen2.5-0.5B-Instruct — small, roughly a thousandth the size of a frontier model. It is trained with LoRA on a single Kaggle GPU. Every experiment runs on 246 answers the model has never seen.

The short version

The model learned the expert’s policy almost perfectly — it opens with the same word 100% of the time and matches the expert’s second move 90% of the time. It still lost 76% of its games. Three separate theories about why were tested, and the first two were wrong. The thing that actually fixed it was not better training data at all.

That arc — a confident diagnosis, a clean experiment, a wrong answer, repeat — is most of what follows. The corrections are marked where they happen.

01

How Wordle is scored

The one mechanic everything else is built on

You guess a five-letter word. Each letter comes back green (right letter, right place), yellow (right letter, wrong place), or grey (not in the word). Six guesses.

There are 2,315 possible answers and 12,972 words you’re allowed to guess. That gap matters enormously and comes up repeatedly: many of the best guesses are words that cannot be the answer, played purely to eliminate possibilities.

Duplicate letters are where it gets subtle

The answer supplies a budget of each letter. Greens claim it first, then yellows left-to-right, and surplus copies come back grey.

32.4% of answers contain a repeated letter, so this is a third of the game, not an edge case.

Internally each pattern is packed into a single number, base-3 by position. Three states, five slots, so 35 = 243 possibilities — which fits in one byte. That is the reason the entire 12,972 × 2,315 table of “what feedback would guess g give against answer a” can be precomputed into 28.6 MiB and held in memory. Every filtering operation afterwards is a table lookup rather than string comparison.

02

The classical solver

Building the teacher — no machine learning anywhere

Before touching a model, we needed something worth imitating. The solver has three layers, deliberately measured separately so you can see what each one buys.

Layer 1 — elimination. After each guess, discard every answer that would have produced different feedback. Pure logic.

Layer 2 — information theory. Among all 12,972 legal guesses, pick the one that splits the remaining candidates most evenly.

Layer 3 — lookahead. Search the game tree several moves deep instead of being greedy.

Two things worth noticing. Perfect elimination alone already solves 98.4% of games — guessing at random among survivors is a decent player. And information theory buys another 0.6 guesses and removes failure entirely.

These numbers reproduce published figures for this word list (SOARE at 5.886 bits, ROATE at 60.42 expected remaining, minimax worst case 168), which is external evidence that the feedback function and entropy computation are correct rather than plausibly-wrong.

The ceiling this sets

A student cannot beat its teacher. Every number later in this page is chasing 3.44, and the gap to it is the only thing that matters.

03

Turning it into training data

And the leak-proofing that took longer than the solver

Run the expert over all 2,315 answers and record every decision it makes: the board state it saw, and the word it played. That gives roughly 8,000 (state → action) examples per policy.

The state is rendered as plain text. This is the entire input the model ever gets:

What the model is never allowed to see

This was the fussiest part of the whole project, because a leak here would invalidate everything downstream and would not necessarily look wrong.

  • The answer. Not a parameter of the renderer, and structurally impossible in the history — a correct guess ends the game.
  • The candidate list, and even how many candidates remain. That number is a solver-side quantity a human player cannot see, and it silently reveals how close you are.
  • Concatenated greens. They render as p1=A p2=L rather than AL___, because once all five are known, the concatenation is the answer.

The 2,315 answers are split by hashing the answer word itself — 2,069 for training, 246 held out — so every policy puts the same words in the test set and comparisons stay honest.

A false alarm worth keeping

The leak audit flagged prompts containing the answer GUESS. It was matching the fixed instruction text — “After each guess…”, “Next guess:” — and GUESS and AFTER happen to be real Wordle answers. The check now scans only the parts of the prompt that vary. Worth mentioning because it is exactly the kind of thing that gets waved away as noise when it might not be.

04

The first SFT run

Three models, identical settings, one clear result

Three LoRA adapters trained on three different expert policies, ~24 minutes each on a T4. Then each played 246 unseen games under strict rules: greedy decoding, first token only, and an invalid guess costs the turn and returns no feedback. No silent repair.

But it had clearly learned something

The mean hides the interesting part. The opening word was correct in 100% of all 246 games. On the states where two different experts disagree, the entropy-trained model picked the entropy expert’s move 90.1% of the time and the other expert’s move 0% — and the tree-trained model mirrored it exactly. It reproduced obscure expert probes verbatim: CLOOT, BARCA, RIYAL, DIRER.

Better still, look at how fast it narrows the field:

The actual failure

The model gets down to about one remaining possibility by turn three, and then cannot say the word. It writes ABOBE when the answer is ABOVE. ABHIE when the answer is ABOVE. AMING when the answer is AGING. Real letters, right pattern, not English words.

And because an invalid guess returns no feedback, the next prompt is nearly identical — so a greedy model emits the same non-word again, and again, until the game ends. One spelling mistake at turn three costs turns three, four, five and six.

05

Diagnosing the failure

Separating “can’t spell” from “can’t think”

Two very different abilities were tangled together, so we built a way to remove one of them. Instead of letting the model generate text, score all 12,972 legal words and play the highest-scoring one. Invalid words become impossible by construction.

This is not filtering the output afterwards. The model never emits free text in this mode — it is asked “which of these words should I play?” and the answer is read off a ranking it produced.

We also built a probe that isolates the endgame precisely: roll the classical solver forward until exactly one possible answer remains, then ask the model to rank all 12,972 words. At that point there is nothing left to decide — only to name.

The verdict was not vocabulary. Even with spelling made impossible to get wrong, the model still lost 56% of games and still lost to random elimination. And the untrained base model scored 7.00 with 100% failure — it answered GUESS to every single prompt, having read “Next guess:” and completed the sentence.

The endgame probe told the sharper story: given a state where one answer was possible, the model ranked the correct word 7.5th out of 12,972 on average, and got it first only 20% of the time.

06

More endgame data

A clean experiment with a null result — and a real finding inside it

Looking at the training data explained why the endgame was weak. There were 1,612 examples of “one answer left, name it” — covering 1,612 different words, exactly one example each. A good expert wins in 3.4 guesses, so it barely visits the endgame; imitating it teaches a 1,612-way lookup table with one sample per entry.

So we manufactured more. Roll out deliberately imperfect games — correct opening word, then randomised continuations, which is what a fallible model actually does — and label the resulting states with the expert. Crucially this gives each word several different routes to itself rather than one memorised path.

The result on games: 108 solved before, 108 solved after. Identical. The retrained model scored 5.6992 against the old model’s 5.6870 — very slightly worse.

But the endgame probe did move, and it moved in a specific place:

Why this matters

All the improvement landed on words the model had never been taught to write, and none on the words it had. That is the signature of learning a procedure rather than memorising answers — the opposite of what a null game result would suggest on its own.

So: a real capability gain that did not translate into a single extra win. Which meant the thing blocking wins was somewhere else entirely.

07

The decoder

Where the actual win came from

Two measurements pointed the same direction. The model contradicted feedback it had already received 31% of the time. And at the endgame, only about 2 of the 12,972 legal words were even consistent with the clues on the board.

So: restrict the model to words that are consistent with every clue so far.

A = { w ∈ legal words : feedback(gj, w) = cj for every past guess j }
A word is admissible only if it would have produced exactly the feedback already seen, for every guess made.

Why this isn’t cheating

This is the distinction the whole approach rests on, so it’s worth being precise. There are two sets that are easy to confuse:

  • The candidate set — possible answers still alive. Computing it requires the answer list. That would be privileged information, and it is never used.
  • The admissible set — legal guesses consistent with the clues. Computing it needs only the board and the public dictionary.

The second is what a hard-mode player works out from their own screen. The model is still never shown the set, its size, or the answer — the restriction happens at the decoder, exactly like restricting to real words.

Why “adaptive” beats always-on

Filtering at every turn is too strict, and the training data says so. The expert’s own second move is inconsistent with its own feedback 59% of the time — it deliberately plays a word that cannot win, to split the space. Forbidding that forbids the expert’s best idea.

So the adaptive decoder probes freely while the board is still open and switches to consistent-only once the possibilities are nearly exhausted. That recovers a further 0.16 guesses, and the contradiction rate rises from 0% to 6.8% — which is the model probing again, exactly as intended.

How much is the model, and how much is the filter?

Fair question, since the filter is doing a lot. So we played the same 246 games with no model at all, picking at random among admissible words: 5.18. The model takes that to 3.76. Its contribution is real and large — and larger under the adaptive decoder, where its learned opening policy replaces a random probe.

08

Tuning the threshold

When should probing stop?

The adaptive decoder needs a switch point: how few consistent words must remain before the model is forced to play one? The first run used 50 as an educated guess. Sweeping it properly:

The last column is the one to watch. As the filter does more, the model’s own contribution falls steadily from 1.79 to 0.57. Sitting on the plateau at 10–20 keeps performance at its best and keeps the model doing meaningful work — which matters if the goal is to improve the model rather than the scaffolding.

A result that looked wrong and wasn’t

Thresholds 1,000 and 1,000,000,000 produced byte-identical results, which looked like a bug. It isn’t: after the first guess there are never more than 769 consistent words, so any threshold above that filters at every turn. They are the same decoder. Identical output was the correct outcome.

09

Where the gap lives

Before trying to close it, find out where it is

The remaining gap is 0.32 guesses. Under the adaptive decoder the model’s job is no longer “write a word” — it is “rank the admissible words”. Ordinary training on a single expert answer teaches one point of that ranking, not the ranking itself. And we already know that more of that kind of data changes nothing: the endgame experiment moved games by exactly zero.

So the next experiment trains on comparisons. Each example is a board state plus two words: one better, one worse, both drawn from the choices the decoder would actually offer.

The final set is 14,923 pairs, weighted toward mid-game states where the model genuinely has to choose between plausible options. Endgame states are largely excluded — the decoder already handles those.

But first: where is the gap?

Before training anything, one measurement. Hand each kind of decision to the classical expert in turn, let the model play everywhere else, and see how much of the 0.32 that recovers. If perfect play in a given situation buys almost nothing, no amount of training aimed there will help.

A bug the audit caught

The first version had a serious flaw: when the decoder restricts the model to consistent words, both words of a comparison must be consistent. But the expert picks from the whole dictionary and often probes with an inconsistent word — so 19% of pairs were teaching a preference about a word the model can never play. It would have trained perfectly happily and quietly poisoned the result. Fixed, re-audited, zero violations.

Three quarters of the entire remaining gap sits in one narrow situation: when 2 to 10 possible words are left. Perfect play there alone would win all 246 games.

The negative row

Handing the expert the opening moves makes things worse, by 0.40. That reads as impossible until you notice what happened: the expert opens with a different word than the model was trained around, so the model gets dropped into positions its training never covered. It is a handoff cost between two playing styles, not evidence the model out-plays the expert. The three rows also don’t sum to the total — they interact at every switchover.

DPO, and why it failed

The preference was learned. The game got worse.

14,923 comparisons, 466 training steps, 44 minutes. By every training metric it worked:

Then it played 246 games:

Why it failed

Accuracy stopped improving at step 75 of 466 — but the margin kept climbing for the other 390 steps. That combination has a specific meaning: the model spent almost the whole run growing more confident about comparisons it already got right, instead of fixing the ones it got wrong.

The reason is in the data. 64% of the comparisons were easy — the difference between a good move and an obviously bad one. Those are cheap to win and they dominated the training signal. The genuinely close calls, the ones that would actually teach something, were the minority.

So the model optimised hard against a target it had already mastered, drifted away from a playing style that worked, and paid for the drift in real games. Its measured contribution fell from 1.412 to 1.241 — confirming the model got worse, rather than something around it changing.

This is the characteristic failure of training on preferences: the score being optimised and the thing actually wanted come apart, and nothing in the training curve says so. Only playing the games does.

The maths

The four formulas that do the work

Skippable if you only want the story. Each of these is used somewhere above.

1. Which guess splits the space best

Group the surviving answers by the feedback a guess would produce. If bucket k holds nk of the n survivors, then pk = nk/n, and:

H(g) = −∑k pk log2 pk      E[rem](g) = (1/n) ∑k nk2
Entropy is bits gained; expected remaining is how many candidates survive on average. Lower is better for the second.

2. Scoring a word instead of writing it

To rank all 12,972 words, we ask the model for the probability it assigns to each one as a complete string:

s(w) = log P(w | prompt) = ∑i log P(ti | prompt, t<i)
Summed over the word’s tokens and the end-of-text token. Including that last one matters: without it, a word whose spelling is a prefix of a longer word is judged under fewer constraints and scores unfairly high.

Doing this naively means 12,972 forward passes per turn. Instead: since every log-probability is negative, a word’s total score can never exceed its first token’s score. That gives an exact upper bound, so words are checked in descending order of that bound and the search stops as soon as the leader beats everything unchecked. The answer is provably identical to scoring all of them — and in practice a trained model needs about 1.4 batches instead of 26.

3. Learning from comparisons

DPO trains on pairs. Let s be the model’s score for a word and sref the score under the frozen starting model:

loss = −log σ( β [ (s(w+) − sref(w+)) − (s(w−) − sref(w−)) ] )
In words: raise the better word and lower the worse one, both measured relative to where you started.

The reference model is not a technicality. That difference term is an implicit reward, and comparing against a fixed starting point is what stops the model drifting away from a policy that already works. β sets how far it is allowed to roam.

4. What GRPO would add

Not yet run. DPO learns from a fixed list of comparisons someone else judged. GRPO instead has the model propose several moves itself, scores them, and shifts weight toward the ones that beat the group average:

advantagei = ( ri − mean(r1..G) ) / std(r1..G)
The group’s own average is the baseline, so no separate value network is needed.

This suits Wordle unusually well: the reward is exactly computable — how many candidates a guess eliminates — rather than a learned approximation, which is where most of the difficulty in this kind of training normally lives. It is last on the list because it is also the most expensive and least stable, and every phase so far has moved less than expected.

12

What we got wrong

Three confident diagnoses, corrected by measurement

The most useful thing in this project is not the final number. It is the sequence of times a well-motivated theory turned out to be wrong, and how each was caught.

Correction 1 — the vocabulary theory

Claim: the model fails because the answers were held out of training, so it has never written those words. Test: make invalid words impossible. Result: bought 0.49 guesses; the model still lost to random elimination. Vocabulary was a contributor, not the cause.

Correction 2 — the endgame-data theory

Claim: the endgame is starved of examples, so teach it more. Test: build 12,145 new endgame states with multiple routes per word. Result: 108 games solved before, 108 after. Exactly zero. The capability improved measurably and won nothing.

Correction 3 — a miscounted statistic

For several days the write-up claimed the endgame had “6 training examples out of 7,173”. That number was real but measured the wrong thing — a narrow flag for boards where all five letters are confirmed. Actual endgame coverage was 1,612 examples. The corrected framing (one route per word, not too few examples) is what led to the experiment that produced the p = 0.031 generalisation result.

Correction 4 — the preference-learning theory

Claim: the model needs to learn comparisons, not single answers. Test: 14,923 preference pairs aimed at the exact situation holding three quarters of the gap. Result: the preference was learned (84% accuracy) and gameplay got significantly worse. The best model remains the one from before.

Two further errors were caught by automated checks rather than by reading: a sampled audit that reported “206 violations” when the true rate was 19%, and a preference dataset where 19% of pairs referred to moves the model could never make. Both would have trained cleanly and produced meaningless results.

Where it stands

3.76 mean, 243 of 246 solved. That beats classical random elimination and edges past letter-frequency heuristics, and sits 0.32 guesses behind a solver that plays perfectly. Most of that came from the decoder rather than the model — but a random player using the same decoder scores 5.18, so the model is contributing about 1.4 guesses of genuine skill.

We now know exactly where the remaining 0.32 is — three quarters of it in a single narrow situation — and that the first attempt to train it away made things measurably worse. The best model is still the one from phase 7.

Model: Qwen2.5-0.5B-Instruct with LoRA. Hardware: one Kaggle T4 session per phase. Evaluation: 246 held-out answers throughout, failures scored as 7 guesses. Every dataset ships with an audit that re-derives each training state from its own prompt and asserts the labels — the checks in this project have caught more real bugs than manual review has.
